# 硬件功能演示 · 实施手册

> 目标不是"做一套系统"，而是**让评委在实物上看见四个功能在发生**。所有工作围绕这一条展开。

---

## 一、必须被"看见"的四件事

| # | 硬件功能 | 载体 | 观众看到什么 | 赛题对应 |
|---|---|---|---|---|
| 1 | 星闪低功耗传感网 | 星闪节点 ×3 | 节点上电自动入网、数据在跑、拔掉一个节点后自愈 | 传输 |
| 2 | 边缘 AI 推理 | 昇腾 Atlas 200I DK A2 | `npu-smi` 利用率跳动、`.om` 模型文件、推理时延数字 | 推理 |
| 3 | 环境感知与决策 | LD2410C 雷达 + SHT40 | 人一走进来，系统状态就变 | 感知 |
| 4 | 执行器物理动作 | 继电器 / 灯 / 风扇 / 红外宝 | 灯亮、风扇转、空调设定点变 | 执行 |

**演示的成败在第 1 和第 2 项**——这两个是赛题的硬要求，也是评委最想验证"是不是真做了"的地方。3、4 是它们的效果证明。

## 二、实施路径

**关键：阶段 0~3 用手上现有的硬件就能做，不用等采购。**

| 阶段 | 目标 | 硬件 | 验收标准（做不到就别往下走） | 预计 |
|---|---|---|---|---|
| **0** | 工具链就绪 | Nano 2 + Purple Pi OH | Nano 2 串口能打印自己的日志；Purple Pi 能跑起一个自建应用 | 2~3 天 |
| **1** | 单节点采集 | Nano 2 + SHT40 | 串口每 5 s 打印温湿度；手捂住传感器数值明显上升 | 2 天 |
| **2** | 数据上行 | Nano 2 + Purple Pi | Purple Pi 能收到并打印节点数据，丢包率 < 1% | 2~3 天 |
| **3** | 执行闭环 | + 继电器 + 灯 | 对着传感器哈气/吹热风，灯在 2 s 内亮起 | 2 天 |
| **4** | 换成星闪 | H3863 ×3 | 3 块板组网，节点数据经星闪到达主机（**赛题核心**） | 1 周 |
| **5** | 接入昇腾 | Atlas 200I DK A2 | 一个 ONNX 转 `.om` 成功，NPU 利用率 > 0，拿到推理结果 | 1 周 |
| **6** | 闭环与彩排 | 全部 | 完整演示流程连跑 5 遍无故障 | 3 天 |

**为什么这么排**：阶段 1~3 用现有硬件把"感知 → 传输 → 决策 → 执行"的逻辑先跑通、跑稳；阶段 4、5 只是**替换传输层和推理层的实现**，业务逻辑不动。这样风险最高的星闪和昇腾被隔离在后半段，前面就算卡住也已经有能演示的东西。

## 三、接线

### 阶段 1：SHT40 接到小熊派 Nano 2

SHT40 模块是标准的 I²C 器件，4 根线：

| SHT40 模块 | Nano 2 |
|---|---|
| VCC | 3.3 V |
| GND | GND |
| SDA | E53 接口的 I²C SDA |
| SCL | E53 接口的 I²C SCL |

> ⚠️ **引脚号以小熊派官方原理图为准**。E53 标准接口的 I²C 在不同批次板子上可能落在不同 GPIO 上，烧写前先对照原理图确认，写错会读不到数据（表现为 I²C 返回非 0 错误码）。
>
> 建议在 SDA/SCL 上各加一个 4.7 kΩ 上拉电阻到 3.3 V（部分模块已板载，先看模块上有没有）。

### 阶段 3：继电器控制灯

| 继电器模块 | Nano 2 |
|---|---|
| VCC | 5 V（继电器线圈需要较大电流，别用 3.3 V） |
| GND | GND |
| IN | 任意可用 GPIO |

灯的市电侧接继电器的常开端（NO），**注意用电安全，演示用低压 LED 灯带更稳妥**。

```
hardware/
├── README.md                    实施手册（阶段划分 / 接线 / 验收 / 留证）
├── 开发流程.md                  ⭐ 在 VSCode 中写代码 → 编译 → 烧录 → 调试的完整流程
├── firmware/
│   └── bearpi_nano2_sensor/     小熊派 Nano 2 传感器节点（OpenHarmony 轻量系统，C）
│       ├── config.h             ⚠️ 部署配置，烧写前必须改
│       ├── sensor_node.c        主逻辑：采集 → 上报 → 指令 → 本地自治
│       ├── sht40.c / .h         SHT40 温湿度驱动（I²C + CRC）
│       ├── relay.c / .h         GPIO 继电器控制

│       ├── BUILD.gn
│       └── README.md            数据格式与分层说明
└── host/
    └── purple_pi_host/          Purple Pi OH 主机端（OpenHarmony 标准系统）
        ├── README.md
        └── ...                  接收节点数据 → 决策 → 下发指令
```

**阶段 4、5 的替换点**（业务逻辑不用改）：

| 现在 | 换成 |
|---|---|
| `udp_link.c` 的 Wi-Fi socket 收发 | 星闪 SLE 的收发接口 |
| 主机端的本地阈值判断 | 送数据给 Atlas，取回推理结果 |

## 五、每阶段要留的证据

参赛和答辩时，"做过"需要有物证。每完成一个阶段，当场采集：

| 阶段 | 留存什么 |
|---|---|
| 1 | 串口日志截图/文本（含时间戳与读数） |
| 2 | 主机侧接收日志 + 丢包统计 |
| 3 | 一段连续动作的视频（哈气 → 灯亮） |
| 4 | 星闪入网日志、链路时延统计、拔节点自愈的视频 |
| 5 | `atc` 转换命令与日志、ONNX 与 `.om` 精度比对结果、`npu-smi info` 截图 |
| 6 | 完整演示视频（**存本机**，作为现场故障时的降级方案） |

> 这些不是"交作业用的"，是答辩时回答"你的 AI 到底跑在哪"的证据链。没有它们，讲得再好也可疑。

## 六、第一步：先让板子跑起来

**不要一上手就写功能代码。** 先用最小的动作验证整条工具链是通的——编译环境、烧录、串口这三样任何一样不通，后面写再多代码都是白搭。这是所有嵌入式项目最大的时间黑洞。

### 今天就能做的（按顺序）

**① 5 分钟 · 确认板子是活的**

1. USB 线把小熊派 Nano 2 接到电脑
2. 装 CH341SER 驱动（没装的话，设备管理器里会是个带感叹号的未知设备）
3. 打开串口终端，波特率 **115200**
4. 按一下板子上的 RESET 键
5. **看到任何输出** → 板子、驱动、串口三样都是好的

看不到输出？换根 USB 线（很多线只有充电线芯、没有数据线芯），或者换个 USB 口。

**② 半小时 · 核对板子型号**

看一眼板子上的丝印：

| 丝印 | 是什么 | 怎么走 |
|---|---|---|
| `Hi3861` | 小熊派 Nano（Wi-Fi 版） | 按本文档 + `开发流程.md` 走 |
| `H3863` / `H2821` | 星闪版（BearPi-Pico 系列） | 流程类似但 SDK 不同，可省掉采购星闪板的钱 |

**③ 半天到一天 · 搭编译环境**

推荐直接用**小熊派官方预装 Ubuntu 镜像**（VMware 的 `.ovf` 文件，默认密码 `bearpi`）——导入即用，省掉手动装工具链的一大堆坑，这是最省时间的一条路。

拿不到镜像就自己装 Ubuntu 18.04+，按 `开发流程.md` 第 1.1 节装工具链。

**④ 半天 · 编译并烧录一个 Hello World**

这一步的目标不是"做出什么功能"，而是**把整个循环完整走一遍**：

```
拉源码 → hb set（选 bearpi_hm_nano）→ hb build -f
      → HiBurn 烧录（921600）→ 串口看日志（115200）
```

**⑤ 验收标准**

串口里能看到你改过的打印。比如把例程里的 `Hello World` 改成 `SparkHub ready`，复位后看到它——**环境就算通了**。

### 同时并行做的事

下单 **SHT40 温湿度模块**（约 ¥15）。它到货后，把 `firmware/bearpi_nano2_sensor/` 编译烧进去，就能看到本文档阶段 1 的效果（串口每 5 秒一条温湿度读数）。

### 卡住了怎么办

**把报错原文发出来**，不要只说"编译失败了"。有用的信息是：

- 完整报错信息（原文，不要转述）
- 你正在做哪一步
- 报错前后的命令

绝大多数问题就三种：驱动没装、波特率搞混（烧录 921600 / 日志 115200）、`include_dirs` 路径不对。都在 `开发流程.md` 第 8 节的坑表里。

### 为什么第一步不是"买硬件"

因为星闪板和昇腾板从下单到能用往往要一两周，而编译环境可能第一天就卡住。**把最可能卡住的事排在前面**——环境通了，硬件一到就能直接上；环境没通，硬件到了也是干等。
