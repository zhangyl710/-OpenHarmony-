# 传感器节点固件（小熊派 Nano 2 / Hi3861）

阶段 1~3 的节点侧代码。编译烧录流程见 [../../开发流程.md](../../开发流程.md)。

---

## 文件

| 文件 | 作用 | 对应阶段 |
|---|---|---|
| `config.h` | **部署配置，烧写前必须改**（Wi-Fi 账号、主机 IP、演示阈值） | — |
| `sensor_node.c` | 主逻辑：采集任务 + 指令任务 + 主机失联时的本地自治 | 1~3 |
| `sht40.c` / `.h` | SHT40 温湿度驱动（I²C + CRC 校验） | 1 |
| `relay.c` / `.h` | 继电器控制（GPIO 输出） | 3 |
| `udp_link.c` / `.h` | Wi-Fi 接入 + UDP 收发 | 2 |
| `BUILD.gn` | OpenHarmony 轻量系统组件定义 | — |

## 数据格式

**节点 → 主机**（每 5 秒一条，`\0` 结尾的文本行）：

```
NODE,N01,T=2543,H=5812,UP=1,TS=123456
```

| 字段 | 含义 |
|---|---|
| `NODE` | 固定前缀 |
| `N01` | 节点 ID（`sensor_node.c` 里的 `NODE_ID`） |
| `T=2543` | 温度，**单位 0.01 ℃**（即 25.43 ℃） |
| `H=5812` | 湿度，**单位 0.01 %RH** |
| `UP=1` | 链路状态，1 正常 / 0 断开 |
| `TS=123456` | 节点开机以来的 tick 数，用于算时延 |

> 用「×100 的整数」而不是浮点，是为了绕开精简 libc 对 `%f` 的支持问题，顺便省空口字节。主机端解析时除以 100 即可。

**主机 → 节点**（控制指令）：

```
CMD,LIGHT,1
```

`1` 吸合（灯亮），`0` 断开。

---

## 刻意的分层

`udp_link.c` 负责通信，`sensor_node.c` 负责业务。**阶段 4 换星闪时，只替换 `udp_link.c` 这一层**，主逻辑一行都不用改。

同理，主机端的决策逻辑后面会从"本地阈值判断"换成"送数据给昇腾推理"，节点侧同样无感。

---

## 演示用的小技巧

`sensor_node.c` 里的 `HostOnline()` 实现了**主机失联时按本地阈值自行动作**。演示时直接**把主机关掉**，节点仍然会点亮灯——这是方案里"去中心化、房间级自治"最直观的展示，评委一看就懂。日志里会有：

```
[local] host offline, autonomous relay -> 1
```
