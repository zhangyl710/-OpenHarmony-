# 星枢 SparkHub

> 基于 **OpenHarmony** + **MindSpore Lite** 的端侧智能家居系统
>
> 让「是否危险」的判断从云端收回到本地，从**单点阈值**升级为**事件识别**

---

## 一、要解决的问题

传统独立烟感只看某一时刻的烟雾绝对浓度，**分不清炒菜油烟、浴室水汽和真实燃烧**。厨房做饭就报警、洗澡就报警，用户在高频误报后干脆关掉告警甚至拆掉电池——**真实火情下的漏报风险反而显著上升**。

纯云端方案识别能力更强，却把可用性绑在外网和云服务上：**网络一断，告警能力归零**，而且家庭传感数据持续上传公有云。

本项目的判断是：**问题不在算法不够强，而在判断依据太单一、决策位置太远。**

---

## 二、做法

用一块 **Purple Pi OH（RK3566）** 作为中控，跑一个 **5124 参数**的时序 CNN，对 **8 通道 × 12 秒**的特征窗口做四分类：

```
正常 / 油烟 / 水汽 / 燃烧
```

**核心设计取舍：**

| 取舍 | 选择 | 理由 |
|---|---|---|
| 云端 vs 端侧 | **端侧** | 3 ms 响应，断网可用，数据不出户 |
| 单点阈值 vs 时序形态 | **时序形态** | 四类事件的差异在"数秒内的变化趋势"而非绝对浓度 |
| 大数据 vs 小模型 | **5124 参数** | RK3566 无 NPU，模型必须小到能实时跑 |
| 单层 vs 三层 | **三层可降级** | 任何单层失效都不导致告警能力归零 |

## 三、实测指标

| 指标 | 数值 | 条件 |
|---|---|---|
| 分类准确率 | **94.91%** | 2791 个滑窗 / 16 会话 / 按会话分层切分 |
| 单次推理延迟 | **3 ms** | RK3566 四核 CPU，单线程 |
| 模型体积 | **27 KB** | 5124 参数 |
| 感知 → 联动 | **约 720 ms** | 含采样、MQTT 往返、推理、指令下发 |
| 燃烧类召回 | **74.6%** | 407 个燃烧窗口漏报 15 个 |
| 正常类误报 | **0 / 1371** | 标定后阈值 θ = 0.35 |

**各类准确率：**

| 类别 | 精确率 | 样本数 |
|---|---|---|
| 正常 | 96.7% | 1371 |
| 油烟 | 97.7% | 471 |
| 水汽 | 88.5% | 542 |
| 燃烧 | 74.6% | 407 |

## 四、系统构成

### 硬件

| 角色 | 型号 | 传感器 / 执行器 |
|---|---|---|
| 中控 | Purple Pi OH（RK3566）· OpenHarmony 6.0（API 20） | 屏幕 + 端侧推理 |
| 感知节点 N01 | BearPi-HM Nano 2（WS63）+ E53_IA1 | SHT30 温湿度、BH1750 光照、LED、电机 |
| 感知节点 N02 | BearPi-HM Nano 2（WS63）+ E53_SF1 | MQ-2 烟雾、蜂鸣器、排风扇 |

### 架构

```
⑤ 交互层    ArkTS 四页签看板：系统总览 / 环境感知 / 安全联动 / 态势解读
              ↑
④ 应用服务层  环境感知 · 设备控制 · 智能问答 · 事件告警
              ↑
③ 端侧智能层  FireCNN 四分类（8 通道 × 12 点 · 5124 参数 · 3 ms）
              三层可降级：规则基线 → 本地 CNN → 云端（可选）
              启动自检（全 0/全 1 差异 < 0.02）+ 温度标定 τ = 0.25
              ↑
② 系统底座层  OpenHarmony 6.0 · 设备抽象 · 数据管理 · 权限模型
             ═══ 业务通信：Mosquitto MQTT over LAN（QoS 0 · 1 Hz）═══
              ↑
① 设备感知层  N01 温湿度/光照/灯/电机　　N02 烟雾/蜂鸣器/排风扇
```

**数据流**：传感器采样 1 Hz → MQTT 发布 → 滑窗 12 点 → FireCNN 推理 → 判定 + 联动 → 界面展示

## 五、三处关键工程处理

模型训练完成后，落到嵌入式运行时还有三道坎。这三处处理是本项目最有价值的部分。

### 5.1 模型自检：把"能加载"与"能推理"分开

`.mindir` → `.ms` 的转换过程中，**部分算子在静态图里推导失败时会被固化为常量**，而转换工具只打印 WARNING，仍返回 `CONVERT RESULT SUCCESS:0`。结果是模型加载成功、输入形状正确、推理无异常，**但任意输入都得到同一组 logits**。

端侧在加载后立即自检：用全 0 与全 1 两组极端输入各推理一次，

$$\Delta=\max_i\left|p_i^{(0)}-p_i^{(1)}\right|<\varepsilon,\qquad \varepsilon=0.02$$

差异过小即判定模型退化，**自动切换规则基线**并提示降级状态。

实测：`selfcheck OK, diff=0.7576`。

### 5.2 概率标定：让告警阈值真正有意义

交叉熵训练的 softmax 输出**不是校准概率**。未标定时，**燃烧类样本自身的 P(燃烧) 中位仅 0.393**——若沿用常见的 0.7 阈值，该阈值在 2791 个样本中从未被触发，**形式上存在、实质上等于全漏报**。

用温度缩放重标定：

$$p_i^{(\tau)}=\frac{\exp(z_i/\tau)}{\sum_j \exp(z_j/\tau)}$$

$\tau$ 由验证集 NLL 网格搜索得到 **0.25**（NLL 0.578 → 0.278）。标定后正常样本 P(燃烧) 上界 0.199、燃烧类中位 0.576，取告警阈值 **θ = 0.35**，正常样本误报 0 次。

> 温度缩放是单调变换，**不改变 argmax，总准确率保持 94.91% 不变**；它改变的是概率的可解释性。

### 5.3 三层可降级：安全结论不被单层否决

| 层级 | 实现 | 特点 |
|---|---|---|
| **L1 规则基线** | 整窗斜率 + 阈值判据 | 白盒、零依赖、永远可用 |
| **L2 本地 CNN** | MindSpore Lite + FireCNN | 主力，3 ms |
| **L3 云端 LLM** | DeepSeek API（可选） | 仅生成建议与识别训练集外事件，**不参与判类** |

**降级规则**：自检失败 / 推理异常 / 滑窗未满 → 保留 L1 结果。

**冲突保护**：规则判燃烧（≥0.5）而模型判低（<0.5）时，**采信规则**。

依据来自一次实测：现场近距离热源使升温速率达 **3.2 ℃/s**，是训练集上限（0.67 ℃/s）的 **4.8 倍**，超出归一化区间。模型输出「正常 0.479 / 燃烧 0.309」，而规则基线依据"温度快升 + 湿度下降"正确判定为燃烧。**没有这条保护，此例即为一次漏报。**

## 八、断网时的行为

| 场景 | 采集 | 端侧判定 | 联动告警 | 云端建议 |
|---|---|---|---|---|
| 断外网 | ✅ | ✅ | ✅ | ❌ |
| Broker 断开 | ✅ | — | ✅ 设备端本地安全 | ❌ |
| 节点掉线 | 单节点降级 | ✅ | ✅ | — |

**设备端本地安全逻辑**：`温度 ≥ 45℃` 或 `烟雾 ≥ 300ppm` 直接驱动蜂鸣器与排风扇，**不依赖任何网络**。

## 九、已知限制

| 限制 | 说明 |
|---|---|
| **训练集覆盖不足** | 2791 窗、16 会话，场景集中在厨房与浴室；其他气溶胶来源（香烟、香薰）未标注 |
| **dTemp 归一化区间偏窄** | 设计范围 `[-1, 1]`，现场实测达 3.2 ℃/s，已加高温兜底但特征区间待扩 |
| **零样本识别未验证** | 机制已在代码中实现（低置信度→大模型识别），但缺少训练集外对照样本，**不作为已达成能力** |
| **固件缺自动重连** | 开机连不上 Broker 时会退出主循环；断线后需重启板子（待修） |
| **无 OTA** | 节点固件只能通过 USB 烧录更新 |
